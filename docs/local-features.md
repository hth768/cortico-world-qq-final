# 配置、数据和验证

## QQ 专用笔记

`qq_memory` 提供 `remember(text)`、`recent(limit)`、`search(query,limit)` 三种 action。查询默认 5 条，最多 20 条；单条最多 4096 UTF-8 字节，固定存储上限 8 MiB。文件位于宿主传入的 `dataDir/qq-notes.jsonl`，不接受路径参数，不写角色文件或系统配置。

保存需要本次宿主上下文包含有效 QQ 会话；来源由宿主提供，桌面单独请求或模型传入来源字段不能伪造。记录含时间、编号、来源、`trust=untrusted` 和普通文本。桌面与 QQ 均可查询，记录不自动拼进角色前缀。坏文件、文件链接/硬链接或直接作为链接的数据目录会拒绝读写。

## 每日提醒额度

`reminder.dailyQuota` 默认 5，最小 1。所有群和私聊按配置时区自然日共用，计数保存到 `dataDir/reminder-quota.json`；按到点处理而非创建数量计数，删除提醒和重启不返还额度。计数先保存，再向主模型推提醒事件；存档损坏或保存失败时停止处理，避免把未知计数当成零。

超过上限的到期提醒标记结束，程序只通过 OneBot 发送普通文字，不调用主模型、语音或视觉辅助模型，不把内容作为 piggyback 事件回灌模型。`reminder.limitMessage` 中 `{limit}` 替换为当前上限，每个会话每天成功提示一次，避免刷屏。失败不回退 AI。普通聊天、创建提醒和额度内提醒仍可能调用模型。

省略 `address` 需要宿主实际投递的唯一 QQ 消息会话。混合多个目标、来源缺失或只有后台提醒时必须明确填写 `group:群号` 或 `private:QQ号`。两种方式都检查有效编号和监听/发送权限。

## Windows 一键启动

在“连接与监听”配置 `napcatLauncher` 为本机 `NapCatWinBootMain.exe` 的完整路径，再点击“启动 QQ 聊天”。按钮先启用插件，随后调用面板 `startNapCat`；插件挂载本身不会启动进程。

只允许 Windows 本地绝对路径和固定 EXE 文件名，拒绝 BAT、UNC、命令字符串和模型传参。启动固定空参数、`shell:false`、工作目录为 EXE 所在目录。没有开机自启或结束 QQ 功能。已连接/6099 管理端口在监听时复用，并用启动等待期及并发锁防止重复；扫码仍在 NapCat 的本机登录页完成。

本按钮以管理端口 `127.0.0.1:6099` 为当前适配目标；其他安装方式或更改管理端口需要另行适配。没有把启动器注册为 AI 工具。

## 开发验证

安装开发依赖后运行 `npm test`，共 64 项，涵盖上游原有测试和新增的时间、额度持久化、固定笔记、模拟启动器与图片下载测试。测试使用临时文件和模拟下载流，不启动真实 QQ 进程或访问外部网络、模型。

控制台构建使用 `npm run build:console`。若宿主不在默认相邻仓库布局，设置 `CORTICO_DIR` 为包含 `src/` 的 Cortico 根目录。构建输出 `dist/console-<hash>.js` 并更新 manifest 的 `webUiClient`，避免长期缓存旧入口。

本次还在配套宿主运行了 180 项集成检查：时间 65、提醒地址 32、额度 22、权限 26、笔记 13、启动器/页面 15、图片 7。图片检查额外使用临时本机 HTTP 服务验证真实 Node fetch 在正文停滞时中止，其他外部服务均模拟；没有真实 QQ 测试发送、模型调用或鼠标操作，未以退出在线 QQ 的方式测试冷启动扫码。

本仓库和当前宿主之间原有的完整 TypeScript 类型检查错误仍需上游单独处理。本分支比较了原版 0.6.24 和迁移版的诊断，修正自身新增的类型问题；不能把“未新增类型错误”说成全项目类型检查通过。

## 图片下载边界

主模型附件使用完整下载 20 秒截止和 8,000,000 字节（8 MB）上限。辅助视觉与表情包收藏使用其已有的 `timeoutMs/maxBytes` 配置。响应头可提前拒绝过大文件；缺少或伪造 `Content-Length` 时，仍按流中实际收到的字节数检查（包括解压后的正文）。超限、超时、HTTP 错误或读取错误均取消下载并返回失败，沿用原有图片占位流程，不增加模型重试。

超时不在收到响应头时清除，而是在全部字节读取结束或失败后清理。取消操作不等待异常流无限返回，避免把同一条串行消息链继续卡住。这些限制针对每个图片下载，不等于给整条多图消息设置总大小或总耗时上限，也没有增加图片内容审核。
