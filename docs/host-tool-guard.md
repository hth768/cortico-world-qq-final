# 宿主工具来源检查：合并前提

QQ 插件只拥有自己的工具，无法单独约束同一主会话里的鼠标、设置、记忆和其他 World 工具。因此本分支的 `allowLocalOperations=false` 必须配合宿主执行边界修改；在未修改的宿主上，不能承诺此开关已拦截其他工具。

`host-tool-guard.patch` 是以 Coopanion 0.2.8 所带 Cortico 源码为基础的参考差异，包含 `src/core/types.ts` 和 `src/core/loop.ts`。它供宿主维护者评审，不应不检查版本就自动覆盖安装目录。宿主源码及其补丁按宿主原项目许可证分发；插件自身保持原 MIT 许可证。

## 宿主契约

1. `ToolCallContext.triggerEvents` 由实际投递给模型的事件复制而来，仅含 `source/type/origin/senderKey`。复制并冻结，模型参数中的来源或授权声明不参与判断。
2. 同次唤醒跨工具轮次累积来源，内部事件不能抹掉已有 QQ 来源。新唤醒从空快照开始；尚未投递的排队事件不得影响当前工具目标。
3. 所有工具（包括 Persona 文件工具和其他 World 工具）都在 handler 边界先经过各 World 的 `checkToolCall`。普通执行和流式提前执行必须共用该包装。
4. 非空拒绝理由返回 `{text, failed:true}`，不调用实际 handler。

插件策略默认允许自身 QQ 工具和 `end_turn`；有 QQ 来源（含后台提醒、内部事件及 QQ/桌面混合轮次）时拒绝其他工具。没有可确认桌面输入的内部轮次也拒绝。独立的桌宠输入/语音/回答或控制台消息才按桌面既有权限执行。用户在本机开启 `allowLocalOperations` 后，只跳过此 QQ 来源限制，底层工具原有授权仍执行。

## 适用边界

- 该检查控制工具执行，不隔离各会话共享的历史、人格和笔记，不能保证回答绝不泄露既有上下文。
- QQ 笔记是普通不可信数据，可能包含错误或注入文本。标记和固定路径不等于消灭提示词注入。桌面用户主动检索这些笔记后仍应将其视为外部资料。
- 此补丁未作为新的宿主 API 版本发布。正式合并时应由宿主维护者确定能力声明、版本要求和兼容策略；本插件 PR 应保持草稿，直到宿主支持得到确认。

## 已做的集成验证

在配套宿主上运行真实 MainLoop、WakeBus、QQWorld 和 CUA 权限处理器，用模拟模型和底层系统操作检查普通/流式路径。验证桌面此前已授权鼠标操作后，QQ 再请求仍被拒绝；也覆盖混合轮次、内部事件、伪造工具参数、下一次独立桌面输入、用户显式打开开关的行为。

同时验证提醒目标使用宿主来源，QQ 专用笔记不能写角色文件，读回恶意笔记后调用本地工具仍被拒绝。没有真实截图、键鼠输入、测试模型或 QQ 消息发送。插件独立测试见 `npm test`；它不替代这里的宿主集成验证。
